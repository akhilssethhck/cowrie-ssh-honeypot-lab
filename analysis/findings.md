# Cowrie Honeypot Findings

## SSH Connection Analysis

A controlled SSH connection was initiated from Kali Linux
against the Cowrie SSH honeypot in a virtualized laboratory
environment.

The connection demonstrated how Cowrie emulates an SSH service
and records interaction with the honeypot.

### Observed Activity

- SSH connection established
- SSH authentication interaction
- User session created
- Commands entered during the session
- Session termination recorded

The activity demonstrates the type of telemetry that can be
collected from an exposed SSH service.

## Authentication Activity

Cowrie recorded the SSH authentication interaction generated
during the controlled test.

Authentication telemetry is useful for identifying suspicious
login behavior against exposed SSH services.

### Detection Opportunities

Authentication data can help identify:

- Repeated failed login attempts
- Brute-force behavior
- Commonly targeted usernames
- Repeated authentication from the same source
- Unusual authentication patterns

In a production environment, these indicators could be used to
generate alerts or contribute to an SSH brute-force detection rule.

## Command Activity

Commands entered during the SSH session were recorded by
Cowrie as part of the honeypot session telemetry.

Command activity is particularly valuable for security
analysis because it can provide insight into an attacker's
intent and behavior.

### Security Relevance

Command telemetry can help identify:

- Reconnaissance commands
- System enumeration
- File and directory discovery
- Privilege-related activity
- Attempts to download or execute files
- Persistence-related commands
- Other suspicious shell activity

In a real security environment, suspicious commands could be
used as indicators for detection rules and incident
investigations.

## Log Information

During the laboratory exercise, Cowrie generated telemetry
associated with the SSH sessions.

The telemetry can contain information such as:

- Connection timestamps
- Source IP addresses
- Usernames
- Authentication attempts
- Commands executed
- Session activity
- Session termination
- Session metadata

This information can be useful for reconstructing SSH activity
and identifying indicators of potentially malicious behavior.

> Note: Raw honeypot logs are not included in this public
> repository to avoid exposing unnecessary network or
> environment-specific information.

## Detection Opportunities

The telemetry generated by Cowrie can support several useful
SSH detection scenarios.

### 1. SSH Brute-Force Detection

Detect repeated authentication attempts from the same source
within a defined time window.

**Example detection logic:**

```text
Multiple failed SSH authentication attempts
from the same source IP within a short period
→ Generate security alert

```

## Security Lessons

This laboratory exercise provided practical experience with
SSH honeypot deployment and security telemetry analysis.

Key lessons learned include:

- SSH services are frequently targeted by automated activity.
- Authentication telemetry can reveal brute-force patterns.
- Command activity can provide useful indicators of attacker behavior.
- Session data can help reconstruct an attack timeline.
- Honeypots can generate valuable telemetry without exposing production systems.
- Security telemetry can be integrated into SIEM platforms for centralized monitoring.
- Detection rules can be developed from observed attacker behavior.

The exercise also demonstrated the importance of analyzing security
events from multiple perspectives, including authentication,
network connections, commands, and session activity.

## Conclusion

The Cowrie SSH honeypot successfully captured controlled SSH
activity during the laboratory exercise.

The project demonstrated how honeypot telemetry can be used to
observe authentication behavior, command activity, connection
patterns, and SSH sessions.

The collected security concepts provide a foundation for building
more advanced detection mechanisms and integrating honeypot data
with SIEM platforms.

Future work will focus on automated log analysis, SIEM integration,
detection engineering, and security dashboards.
